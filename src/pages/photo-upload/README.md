# 사진 업로드 (FE 이슈 #15)

- `/upload`: 로그인 필요. JPEG/PNG 최대 10MiB, 여러 사진을 한 장씩 확인 후 업로드합니다.
- `POST /api/photos`: `image` 파일 + `data` JSON Blob, 기존 API 클라이언트와 JWT 사용.
- 성공한 사진은 재전송하지 않으며 실패한 사진만 재시도합니다. 업로드 중 취소는 제공하지 않습니다. 응답을 받기 전 페이지를 떠나면 서버 처리 여부가 불확실하므로 이탈 경고를 표시합니다.
- EXIF 촬영 시각이 있으면 수정하지 않고 사용합니다. 직접 입력은 KST 로컬 시각이며 Z/UTC 변환을 하지 않습니다. 최종 EXIF 인증과 행정동 판정은 서버가 수행합니다.

## 임시 색상 알고리즘
팀 최종 확정 전 MVP 구현입니다. `color-analysis.ts`에 UI와 분리했습니다.
BE ColorBins.HEX와 같은 40색 순서, 긴 변 최대 256px, 투명 픽셀 제외/부분 투명도 가중, HSV 채도 0.15로 무채색 후보 분리 후 Lab 최근접 분류를 사용합니다. bins는 정규화하고 palette는 빈도순 5개, 부족하면 최다색으로 보충합니다. 보충색의 표시 비율은 0입니다.

## 수동 확인 필요
실제 로그인 후 사진 선택/드롭 → 네 메타데이터 상태 → 지도 위치 확정 → 업로드 → 부분 실패 재시도 → 완료 화면 순서로 확인합니다. 백엔드 연결 및 Kakao 키/허용 도메인이 필요합니다. 현재 빌드에서 VITE_KAKAO_MAP_KEY 미설정 경고가 있습니다. 실제 AWS 업로드, 로그인 만료 후 재로그인, 모바일 레이아웃 및 Kakao 팝업은 실환경 검증이 남아 있습니다.

## 디자인 차이
완료 화면은 실제 동 경계의 개략도와 동별 업로드 수를 보여줍니다. 정확한 촬영 위치나 다른 사용자 픽셀은 표시하지 않습니다. 새로 칠한 동 수는 firstInCell로 정확히 계산할 수 없어 표시하지 않습니다. HEIC는 백엔드 미지원으로 제외합니다. 행정동 선택은 기존 API의 구·동 선택 목록을 사용합니다.
